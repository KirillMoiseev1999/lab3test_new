# Сервис учёта подписок — новая версия

Лабораторная работа № 3, часть 2. Реализация по ТЗ от 27 ноября 2026 года: регистрация, вход и выход, подписки, фактические платежи, история и расходы. Прогноз, календарь и восстановление пароля исключены из согласованного объёма. Предыдущий проект не изменён.

## Структура

```text
Subscriptions.sln
src/
  Subscriptions.Api/              HTTP-контроллеры, Bearer, Swagger, обработка ошибок
  Subscriptions.Business/         Сервисы, DTO, валидация, интерфейсы зависимостей
  Subscriptions.DataAccess/       EF Core, сущности, конфигурации, репозитории, миграции
tests/
  Subscriptions.Business.Tests/   Изолированные NUnit-тесты с Moq
  Subscriptions.IntegrationTests/ HTTP и настоящая временная SQLite
scripts/
  Smoke.ps1                      Проверки через curl.exe
  Coverage.ps1                   Запуск тестов и вывод покрытия Business
docs/
  API.md                         Правила контракта и примеры
  openapi.json                   Контракт, выгруженный из работающего приложения
  Проверка.md                    Фактический протокол проверки
```

Это один запускаемый монолит с тремя слоями. API ссылается на Business и DataAccess; DataAccess ссылается на Business; Business не ссылается на другие проекты и не использует EF Core. Контроллеры вызывают сервисы; запросы к данным выполняют репозитории. Классы, DTO и интерфейсы находятся в отдельных файлах.

## Требования к компьютеру

.NET SDK с поддержкой net8.0 (проверено SDK 9.0.318), ASP.NET Core Runtime 8 и Windows PowerShell с curl.exe для смоук-проверок. SQLite-сервер отдельно не нужен. Версии NuGet-пакетов указаны в проектах: EF Core 8.0.33, Swashbuckle 6.6.2, NUnit 3.14.0, Moq 4.21.0, Test SDK 17.12.0, адаптер NUnit 4.5.0, Coverlet 6.0.0. Доступ к NuGet нужен при первом восстановлении.

## Запуск

Открыть PowerShell в папке, содержащей этот README и Subscriptions.sln. Все приведённые команды выполняются из неё.

```powershell
dotnet restore Subscriptions.sln
dotnet build Subscriptions.sln --no-restore
dotnet dev-certs https --trust
dotnet run --project src/Subscriptions.Api --launch-profile https
```

Swagger: https://localhost:7028/swagger . При первом запуске начальная миграция автоматически создаёт `src/Subscriptions.Api/subscriptions-v2.db`. Повторный запуск сохраняет данные. Старую учебную БД переносить сюда не нужно. Если порт занят старой версией сервиса, остановить её перед запуском новой.

При желании применить миграции вручную:

```powershell
dotnet tool restore
$dbPath = Join-Path $PWD 'src/Subscriptions.Api/subscriptions-v2.db'
dotnet ef database update --project src/Subscriptions.DataAccess --startup-project src/Subscriptions.Api --connection "Data Source=$dbPath;Foreign Keys=True"
```

Изменение схемы оформляется новой миграцией, а не ручным изменением БД. Для другого файла БД задать переменную `ConnectionStrings__Subscriptions` со строкой подключения перед запуском. Автоматическое применение миграций отключается настройкой `Database:ApplyMigrations=false`; в этом случае схему нужно развернуть заранее.

## Проверка

При работающем API открыть вторую консоль:

```powershell
& ./scripts/Smoke.ps1
```

Скрипт отправляет настоящие HTTP-запросы через curl.exe, создаёт уникальные учебные учётные записи и проверяет ответы и значимые поля. Он не очищает существующие данные, не выводит токены и завершится ошибкой при несовпадении результата. Запускайте его на учебной БД. Для другого адреса: `& ./scripts/Smoke.ps1 -BaseUrl 'https://localhost:7049'`.

```powershell
dotnet test Subscriptions.sln
& ./scripts/Coverage.ps1
```

Для тестов не требуется запущенный API. Модульные тесты подменяют хранилища, часы и криптографические адаптеры. Интеграционные тесты поднимают приложение внутри процесса и для каждого теста создают отдельную SQLite в системной временной папке. Используются настоящие миграции, ограничения и транзакции; по окончании временные базы удаляются.

Coverlet показывает покрытие строк и ветвей. Скрипт выводит всю сборку Business, без исключения сервисов. Покрытие операторов отдельно не измерено: выполнение требования 90% операторов этим результатом не подтверждается. Подробные результаты и ограничения приведены в [протоколе](docs/Проверка.md).

## Решения реализации

Пароли хешируются PasswordHasher с солью. Токен — 32 случайных байта в шестнадцатеричной записи; в БД хранится только SHA-256 токена. Срок сессии — 30 минут, logout отзывает только текущую сессию. Пять неудачных входов за последние 15 минут блокируют следующий вход; границы проверяются через внедряемые часы.

Деньги в Business представлены decimal, в SQLite — long в сотых долях. Преобразование выполняет DataAccess. Разные валюты не складываются. Фактический платёж не изменяет плановую дату. Архивация сохраняет подписку и историю, допускает дальнейшие платежи. Категория для отчёта берётся из текущей подписки.

Платёж и запись ключа сохраняются одной транзакцией. SQLite immediate-транзакция получает блокировку записи до проверки ключа: параллельный запрос ждёт и затем читает результат первого. Уникальный индекс `(UserId, Key)` дополнительно защищает от дублей. При повторе после 24 часов запись ключа обновляется, старый платёж сохраняется. Это решение рассчитано на учебный монолит с SQLite; нагрузочные испытания не проводились.

Для отправки преподавателю загрузить решение в репозиторий вместе с `src`, `tests`, `scripts`, `docs`, `.config`, `.gitignore` и `Directory.Build.props`. Папки bin, obj, TestResults, .vs, .tools и файлы БД исключены из Git. Секреты и рабочие данные для запуска не требуются.
