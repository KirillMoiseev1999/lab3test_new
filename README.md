# Сервис учёта подписок

Учебный бэкенд для второй части лабораторной работы № 3, упрощённый по дополнению преподавателя. Хранит подписки и фактические платежи пользователя, показывает историю и расходы за период. Списания выполняют провайдеры контента: сервис не связан с банками и не принимает данные карт.

Все суммы в рублях, без поля валюты. Категорий, тарифов, разных ролей, прогнозов, календаря и восстановления пароля нет. Периодичность и следующая дата хранятся как сведения о подписке. Платежи пользователь вносит вручную. Идемпотентность записи платежей сохранена.

## Структура решения

```text
Subscriptions.sln
src/
  Subscriptions.Api/              Контроллеры, авторизация, Swagger, ошибки
  Subscriptions.Business/         Сервисы, DTO, валидация, интерфейсы
  Subscriptions.DataAccess/       EF Core, сущности, хранилища, миграции
tests/
  Subscriptions.Business.Tests/   Изолированные NUnit-тесты с Moq
  Subscriptions.IntegrationTests/ HTTP и временная настоящая SQLite
scripts/
  Smoke.ps1                      Проверка через curl.exe
  Coverage.ps1                   Тесты и покрытие всей сборки Business
docs/                            Требования, ТЗ, промт, контракт и протокол
```

Это монолит с одним запускаемым API и тремя слоями. API ссылается на Business и DataAccess, DataAccess реализует интерфейсы Business. Business не зависит от ORM и HTTP. Запросы к БД находятся только в DataAccess, включая проверку готовности. Каждый класс и интерфейс размещён в отдельном файле.

## Запуск

Открыть PowerShell в папке с этим README и Subscriptions.sln. Нужен SDK с поддержкой .NET 8, для смоук-скрипта — curl.exe. Отдельный сервер SQLite не нужен. Версии зависимостей зафиксированы в проектах; проверено с SDK 9.0.318.

```powershell
dotnet restore Subscriptions.sln
dotnet build Subscriptions.sln --no-restore
dotnet dev-certs https --trust
dotnet run --project src/Subscriptions.Api --launch-profile https
```

Swagger: https://localhost:7028/swagger . Если порт занят прежним API, сначала остановить его. Запуск автоматически применяет миграции к новой `src/Subscriptions.Api/subscriptions-simple.db`. При повторном запуске данные сохраняются. `subscriptions-v2.db` и старый проект не подключаются и не изменяются.

Для ручного применения миграций:

```powershell
dotnet tool restore
$dbPath = Join-Path $PWD 'src/Subscriptions.Api/subscriptions-simple.db'
dotnet ef database update --project src/Subscriptions.DataAccess --startup-project src/Subscriptions.DataAccess --connection "Data Source=$dbPath;Foreign Keys=True"
```

В истории миграций сохранена InitialSchema и добавлена SimplifyTeachingScope. Вторая убирает категории, валюты и LoginAttempts; итоговая схема содержит пять сущностей: User, Session, Subscription, Payment, IdempotencyRecord. Обе миграции применяются к новому файлу. Исторические поля в первой миграции не являются частью текущей модели. Предыдущую БД не нужно переносить или вручную изменять.

Для другого файла БД перед запуском задать `ConnectionStrings__Subscriptions`. Автоматическое применение миграций отключается настройкой `Database:ApplyMigrations=false`, если схема развёрнута заранее.

## Проверка

В другой консоли при запущенном API:

```powershell
& ./scripts/Smoke.ps1
```

Скрипт создаёт уникальные учебные аккаунты и отправляет запросы через curl.exe. Проверяет статусы и данные, не выводит токены, не удаляет существующие записи. Использовать на учебной БД. Для другого адреса: `& ./scripts/Smoke.ps1 -BaseUrl 'https://localhost:7049'`.

```powershell
dotnet test Subscriptions.sln
& ./scripts/Coverage.ps1
```

Для тестов не нужен запущенный API. Модульные тесты подменяют хранилища, часы и криптографические адаптеры. Интеграционные поднимают приложение в процессе с отдельной временной SQLite на каждый тест, применяют настоящие миграции и удаляют временные данные после проверки.

Результат проверки редакции 2: **102 теста прошли (86 модульных и 16 интеграционных)**; **30 curl-запросов прошли**. Coverlet: **99,53% строк и 100% ветвей всей сборки Business**, без исключения сервисов. Покрытие операторов отдельно не измерено, поэтому критерий 90% операторов остаётся неподтверждённым. Подробности в протоколе.

## Основные правила

У пользователя есть только доступ к своим данным. Пароли защищены PasswordHasher с солью. Токен сессии действует 30 минут; в БД хранится его SHA-256. Выход отзывает только текущий токен. Счётчика неудачных входов в этой версии нет.

Деньги обрабатываются decimal в Business и хранятся целым числом копеек в SQLite; преобразования выполняет DataAccess. Цена подписки и сумма фактического платежа могут различаться. DELETE архивирует, сохраняя историю и возможность записи платежей. PUT может восстановить подписку. Фактический платёж не переносит следующую дату.

Расходы содержат total и bySubscription: общую сумму и суммы по подпискам за [from,to). Названия текущие, архивные платежи включены, расчётов по периодичности нет. Пустой результат — 0.00 и пустой список.

Idempotency-Key уникален для пользователя. Повтор тех же подписки, суммы и даты в течение 24 часов возвращает тот же платёж; другие данные дают 409. Ровно через 24 часа ключ можно использовать заново. Платёж и ключ сохраняются одной immediate-транзакцией SQLite; уникальный индекс защищает от дублей. Конкурентные повторы проверены тестами.
