# Протокол проверки новой версии

> Этот протокол относится к реализации до упрощения. Его результаты не подтверждают соответствие редакции 2 требований и API-контракта. После переработки кода будет выполнена новая проверка. Исходная копия сохранена в archive/before-simplification.

Дата: 27 ноября 2026 года. Среда: Windows, .NET SDK 9.0.318, целевая платформа net8.0. Проверялось решение SubscriptionsV2, созданное отдельно от предыдущей версии.

## Сборка и тесты

Сборка всех пяти проектов завершена без предупреждений и ошибок. Пройдены 100 тестов: 87 изолированных модульных и 13 интеграционных; ошибок и пропусков нет. Интеграционные тесты выполнялись с настоящей временной SQLite и начальной миграцией.

| Область | Подтверждённое поведение |
|---|---|
| Регистрация | Нормализация email, проверка формата, хеширование, уникальность и параллельная регистрация дубликатов |
| Сессии | Вход, 30 минут действия, отзыв только текущей сессии, пять неудач за 15 минут и точные границы времени |
| Подписки | Создание, чтение, замена, архивация и повторная архивация; фильтры и пагинация; запрет доступа другому пользователю |
| Платежи | Проверки суммы, валюты и даты; разрешение для архивных подписок; запрет изменения валюты при наличии истории |
| Повторы | Повтор с теми же данными возвращает тот же ID; изменение четырёх реквизитов даёт конфликт; ключ доступен вновь ровно через 24 часа |
| Конкуренция | Четыре параллельных запроса с одним ключом создают один платёж и одну запись ключа |
| История и расходы | Полуинтервал дат, пагинация, отдельные валюты, текущая категория, сохранение истории при архивации |
| База | Внешние ключи, откат при ошибке после записи внутри транзакции, сохранение данных при повторном запуске приложения |
| HTTP | Все 12 операций присутствуют в OpenAPI; обязательная авторизация; ошибки валидации, лишние JSON-поля и некорректный GUID |

При тестировании обнаружено незакрытое соединение после транзакционных операций. В AtomicExecutor добавлено гарантированное закрытие в finally. После исправления повторный полный запуск завершился успешно. В тесте нарушения внешнего ключа сообщение EF Core об ошибке ожидаемо: тест проверяет, что неправильная запись отклоняется.

## Покрытие

Измеритель: Coverlet 6.0.0, формат Cobertura, отдельный запуск Subscriptions.Business.Tests. Измерена вся сборка Business: сервисы, валидация, модели, DTO и ошибки, без исключения неудобных классов или ветвей.

| Объект | Строки | Ветви |
|---|---:|---:|
| Вся сборка Subscriptions.Business | 99,56% | 100% |
| AuthService, SubscriptionService, PaymentService, ExpenseService | 100% | 100% |
| InputValidator | 100% | 100% |

Непокрытая строка сборки относится к чтению свойства исключения, которое проверяется на уровне HTTP интеграционными тестами. Полный Cobertura-отчёт генерируется в TestResults. Скрипт scripts/Coverage.ps1 повторяет измерение и выводит итог по всей сборке Business.

Требование не менее 80% ветвей подтверждено. Покрытие строк превышает 90%, однако это не отдельная метрика операторов. Покрытие операторов не измерялось, поэтому критерий 90% операторов остаётся неподтверждённым. Для его формального закрытия требуется отдельный согласованный измеритель операторов либо подсчёт выполненных операторов; проценты строк не подменяют этот результат.

## Смоук-проверка curl

Настоящее приложение запущено через Kestrel на отдельном локальном HTTPS-порту 7049, чтобы не мешать старой версии на 7028. Применена миграция к отдельной учебной БД. Выполнен scripts/Smoke.ps1: все 25 HTTP-запросов и проверки полей прошли.

Проверены: готовность 200; регистрация 201 и дубликат 409; вход 200; создание 201, чтение и фильтр 200; изменение цены 200; платёж 201, повтор с тем же ID 201 и конфликт 409; история с единственным платежом 200; расходы 100.00 RUB; доступ второго пользователя 404; неверная сумма и размер страницы 400; архивация и её повтор 204, чтение статуса archived 200; платёж архивной подписке 201; выход 204 и использование отозванного токена 401.

Все 12 маршрутов охвачены этим прогоном. Более подробные временные и конкурентные сценарии выполнялись интеграционными тестами. Скрипт curl можно запускать повторно: адреса email и ключи каждый раз новые. Контракт docs/openapi.json выгружен из работающего сервера.
