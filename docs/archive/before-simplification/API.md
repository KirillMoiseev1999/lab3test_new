# Контракт API

Базовый путь `/api/v1`, JSON UTF-8, локальный HTTPS. Машиночитаемый контракт: [openapi.json](openapi.json). Интерактивная документация доступна по `/swagger`.

## Маршруты

| Метод | Путь после /api/v1 | Успех | Назначение |
|---|---|---|---|
| POST | /auth/register | 201 | Регистрация |
| POST | /auth/login | 200 | Получение токена |
| POST | /auth/logout | 204 | Отзыв текущей сессии |
| POST | /subscriptions | 201 | Создание подписки |
| GET | /subscriptions | 200 | Список собственных подписок |
| GET | /subscriptions/{id} | 200 | Получение подписки |
| PUT | /subscriptions/{id} | 200 | Замена редактируемых полей |
| DELETE | /subscriptions/{id} | 204 | Архивация |
| POST | /subscriptions/{id}/payments | 201 | Запись платежа |
| GET | /payments | 200 | История платежей |
| GET | /analytics/expenses | 200 | Фактические расходы |
| GET | /health/ready | 200, 503 | Соединение с БД и схема |

Регистрация, вход и готовность доступны без токена. Остальные операции требуют `Authorization: Bearer <accessToken>`. Владелец определяется сервером. Чужая и отсутствующая подписка дают одинаковый 404. Некорректный GUID — 400. Лишние поля JSON запрещены.

## Входные данные

Регистрация и вход:

```json
{"email":"student@example.com","password":"Lab3-demo-pass-2026"}
```

Email обрезается по краям; сравнение после приведения к нижнему регистру. Пароль 12–128 символов без обрезания. Регистрация возвращает `id,email`; дубликат — 409. Вход возвращает `accessToken,tokenType,expiresAt`. Неверный пароль — 401, превышение лимита попыток — 429.

Создание и PUT подписки:

```json
{"name":"Music","category":"Media","price":"399.00","currency":"RUB","frequency":"monthly","nextPaymentDate":"2026-12-01","status":"active"}
```

Все поля обязательны. Имя 1–100, категория 1–50 символов после обрезания. Цена — строка от 0.01 до 999999999.99, точка и не более двух дробных знаков. Валюты: RUB/USD/EUR; периодичность monthly/yearly; статусы active/paused/archived. Дата — существующая дата yyyy-MM-dd, хранится как реквизит без автоматического переноса. Ответ содержит те же поля и `id`. PUT позволяет восстановить архивную подписку; при наличии платежей изменение валюты даёт 409. DELETE повторно возвращает 204.

Список: необязательные `status,category,page,pageSize`. Фильтры сочетаются через И. Страница от 1, размер 1–100, по умолчанию 1 и 20. Сортировка по nextPaymentDate, затем id, по возрастанию. Ответ:

```json
{"items":[],"page":1,"pageSize":20,"totalCount":0}
```

Создание платежа требует один заголовок `Idempotency-Key` длиной 1–128 после обрезания:

```json
{"amount":"100.00","currency":"RUB","paidOn":"2026-11-27"}
```

Сумма имеет ограничения цены; валюта совпадает с подпиской, paidOn не позже текущего дня UTC. Ответ: `id,subscriptionId,amount,currency,paidOn`. Платежи архивной подписки разрешены. Ключ уникален в пределах пользователя. В течение 24 часов совпадение subscriptionId, нормализованной суммы, валюты и даты возвращает первоначальный ответ и 201; изменение любого реквизита — 409. В момент достижения 24 часов ключ можно использовать заново.

История требует `from,to`, допускает `subscriptionId,page,pageSize`. Период `[from,to)`, from строго раньше to. Сортировка paidOn по убыванию, id по возрастанию. Ответ имеет ту же структуру страницы. Чужой subscriptionId даёт 404. Расходы требуют `from,to`, включают историю архивных подписок:

```json
{"byCurrency":[{"currency":"RUB","amount":"100.00"}],"byCategory":[{"category":"Media","currency":"RUB","amount":"100.00"}]}
```

Пустой результат содержит пустые массивы. Денежные ответы всегда строки с двумя знаками. Категория берётся из текущей подписки; валюты возвращаются раздельно.

## Ошибки

```json
{"code":"validation_error","message":"Некорректные данные.","requestId":"...","errors":{"price":["Сумма должна быть положительной."]}}
```

400 — входные данные; 401 — отсутствующая, истёкшая или отозванная сессия; 404 — отсутствующий/чужой объект; 409 — дубликат email, конфликт валюты или ключа; 429 — лимит входа; 503 — недоступная БД; 500 — непредвиденная ошибка. Словарь errors используется для валидации. Стеки исключений клиенту не возвращаются.
